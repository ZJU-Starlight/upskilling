# 内容维护指南

本手册用于存储社团内训课件、示例和练习材料。内容维护包括错误修正、说明补充和课程资料归档，修改流程如下。

## 文稿规范

正文采用正式、客观的陈述语气，直接说明概念、功能、条件和结果。标题按内容主题命名，操作步骤明确说明所需动作。避免口号式、拟人化、鼓励式表述和无实际信息的修饰语。源码示例与对应的渲染结果使用一致的文本。

## 修改现有内容

1. 在仓库中找到对应的 `docs/` 下 Markdown 文件。
2. 修改内容，使用本地预览检查显示。
3. 提交 Pull Request，说明修改解决了什么问题。
4. 等待构建检查通过，再由维护者合并。

## 新增一次内训

在 `docs/training/` 下创建 `session-XX/` 目录，至少提供课程总览、主体课件和练习。随后更新课程索引与 `mkdocs.yml` 的导航。

各节课件采用以下结构：

> 学习目标 → 内容说明 → 源码与渲染结果 → 常见错误 → 练习。

只归档已经准备好的课程，避免留下没有内容的导航入口。文件名使用简短英文和连字符，页面标题使用清楚的中文。

## 示例与图片

- 示例应包含复现所需的完整内容，并保留与教学目标直接相关的代码。
- 展示 Markdown 源码时，外层使用四个反引号，保护内层三反引号代码块。
- 图片放入 `docs/assets/images/`，填写替代文本，并使用相对路径引用。
- 图表和公式要检查源码、直接打开页面和从其他页面跳转后的效果。
- 区分通用 Markdown、编辑器功能与本站扩展，方便读者理解预览差异。

## 作业材料

第三次内训的作业源文件放在 `homework/session-03/`。更新后，在仓库根目录运行：

```bash
python scripts/package_homework.py
```

打包结果为 `docs/assets/downloads/session-03-homework.zip`。题目和参考答案分开存放，保留作业使用的图片，确保解压后可以独立完成。

## 提交前检查

在安装站点依赖的环境中执行：

```bash
python scripts/package_homework.py
zensical build --clean --strict
python scripts/check_site.py
```

最后在浏览器确认修改页面的排版、链接、图片和手机宽度下的阅读效果。GitHub Actions 会再次执行打包、构建和链接检查。
